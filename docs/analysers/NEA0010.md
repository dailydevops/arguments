# NEA0010: Use ArgumentException.ThrowIfNullOrEmpty for collections

| Property                            | Value                                                    |
| ----------------------------------- | -------------------------------------------------------- |
| **Rule ID**                         | NEA0010                                                  |
| **Title**                           | Use ArgumentException.ThrowIfNullOrEmpty for collections |
| **Category**                        | Maintainability                                          |
| **Fix is breaking or non-breaking** | Non-breaking                                             |
| **Enabled by default**              | Yes, as suggestion                                       |
| **Applicable languages**            | C#                                                       |

## Cause

Code checks a collection or array argument for `null` or emptiness and then conditionally throws an [ArgumentException](https://learn.microsoft.com/dotnet/api/system.argumentexception) or [ArgumentNullException](https://learn.microsoft.com/dotnet/api/system.argumentnullexception).

## Rule description

There is no built-in Roslyn analyzer for this pattern — the collection overloads of `ArgumentException.ThrowIfNullOrEmpty` are throw-helpers provided by [NetEvolve.Arguments](https://www.nuget.org/packages/NetEvolve.Arguments/) itself, not the BCL, so this rule always fires regardless of target framework. For the `string` overload, see [NEA0002](NEA0002.md).

The condition must be `<null check> || <empty check>`, with both sides referring to the same argument. Any null-check shape recognized by [NEA0001](NEA0001.md) is accepted on the left (`is null`, `== null`, `ReferenceEquals(arg, null)`, negated forms). The following empty checks are accepted on the right:

| Empty check                             | Notes                                         |
| --------------------------------------- | --------------------------------------------- |
| `!arg.Any()`                            | LINQ `Enumerable.Any()` without a predicate   |
| `arg.Count == 0` / `0 == arg.Count`     | `Count` property                              |
| `arg.Count() == 0` / `0 == arg.Count()` | LINQ `Enumerable.Count()` without a predicate |
| `arg.Length == 0` / `0 == arg.Length`   | Single-dimensional arrays only                |

The rule only fires when the argument's static type makes `ArgumentException.ThrowIfNullOrEmpty(arg)` bind unambiguously to a behavior-preserving overload:

| Argument type                                                                                        | Reported | Reason                                                                                                                                                                                                                                              |
| ---------------------------------------------------------------------------------------------------- | -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `T[]`                                                                                                | Yes      | Binds to the `T[]` overload.                                                                                                                                                                                                                        |
| `ICollection<T>`, `IList<T>`, or any type implementing only `ICollection<T>`                         | Yes      | Binds to the `ICollection<T>` overload.                                                                                                                                                                                                             |
| `IReadOnlyCollection<T>`, `IReadOnlyList<T>`, or any type implementing only `IReadOnlyCollection<T>` | Yes      | Binds to the `IReadOnlyCollection<T>` overload.                                                                                                                                                                                                     |
| `List<T>`, `HashSet<T>`, `Dictionary<TKey, TValue>`, and other types implementing both interfaces    | No       | The call is ambiguous between the `ICollection<T>` and `IReadOnlyCollection<T>` overloads (CS0121), so the fix would not compile.                                                                                                                   |
| `IEnumerable<T>` (and types implementing only `IEnumerable<T>`)                                      | No       | That overload only throws for an empty sequence when its count can be determined without enumerating (`TryGetNonEnumeratedCount`), so replacing a manual `!arg.Any()` check on a lazily-evaluated sequence would silently drop the emptiness check. |
| Generic type parameters, `string`, and multi-dimensional arrays                                      | No       | Not covered by the collection overloads, or `string` is already covered by NEA0002.                                                                                                                                                                 |

Checks in the reversed order (`arg.Count == 0 || arg is null`) are not reported, because they dereference the argument before checking it for `null` and therefore throw `NullReferenceException` instead.

## Example

```csharp
void M(IReadOnlyList<int> arg)
{
    if (arg is null || arg.Count == 0)
        throw new ArgumentException(nameof(arg));
}
```

## Fix

```csharp
void M(IReadOnlyList<int> arg)
{
    ArgumentException.ThrowIfNullOrEmpty(arg);
}
```

The throw-helper throws `ArgumentNullException` (which derives from `ArgumentException`) when the argument is `null`, and `ArgumentException` when it is empty.

## How to fix violations

Use the code fix (lightbulb menu), or replace the `if` block manually with `ArgumentException.ThrowIfNullOrEmpty(arg)`.

## When to suppress warnings

It's safe to suppress a violation of this rule if you're not concerned about the maintainability of your code, or if the finding is a false positive.

## Suppress a warning

```csharp
#pragma warning disable NEA0010
// The code that's violating the rule is on this line.
#pragma warning restore NEA0010
```

```ini
[*.cs]
dotnet_diagnostic.NEA0010.severity = none
```
